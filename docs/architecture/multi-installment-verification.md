日期：2026-10-18。

第一阶段在现有未提交修改上增加多分期后端能力，保持旧账户 `legacy` 模式。
没有自动转换旧计划、回填旧凭证或重算历史余额。没有执行生产迁移、启动正式
账本服务、访问真实附件、暂存、提交或推送。

## 实施与兼容范围

| 范围 | 结果 |
|---|---|
| 账户与多计划 | 新账户可显式选择 `managed`；同账户多个计划分别保留本金、已入账利息、预计利息及已付累计 |
| 付款 | 一次资金变化对应一个不可变操作；显式分到多个计划、未归计划欠款和未分配款 |
| 延后分配与重分配 | 消耗原付款额度，不重复扣资金；替换分配在一个事务内完成 |
| 撤销 | 按原始实际差量反向处理；先撤销有效后续分配；不覆盖之后的其他交易 |
| 并发与幂等 | 用户行锁先于幂等查询，父付款和计划使用数据库行锁及当前状态校验 |
| 导入回滚 | 普通交易和受管理交易混合批次原子回滚；受管理部分走债务撤销路径 |
| 新模式备份 | `2.5` 保存计划、操作、分配、账户影响及交易引用；恢复前验证完整性 |
| 旧模式备份 | 纯旧模式仍导出 `2.4`；保留 `2.1` 至 `2.4` 恢复能力 |
| 附件 | 撤销后的软删除交易仍保留附件引用，沿用既有 GC 和备份保留规则 |
| Web 与依赖 | 本阶段没有修改 Web 业务源码或依赖；保留现有技术栈及已接受兼容例外 |

## 已复现并修复的审查反例

| 修复前反例 | 修复后的要求 |
|---|---|
| 锁等待后使用旧父付款状态，给已撤销付款追加分配 | 统一用户写锁后，取得账户和付款锁并重新读取；拒绝已撤销父付款 |
| 独立计划取消与利息登记并发，出现已取消但仍欠利息 | 先锁计划再查依赖；取消前余额与已付累计均须为零 |
| 独立计划备份改成 `2.4` 后丢失新集合并清空目标 | 在版本解码丢弃字段前拒绝旧版本中的新集合 |
| 修改子分配的父付款，借用其他付款未分配额度 | 按父付款验证有效子分配累计额度 |
| 向新模式备份追加无凭证普通流水，统计与余额脱离 | 触及新模式账户的流水必须有关联操作；期初投影也明确绑定 |
| 导入到新模式账户成功，批次回滚却被普通删除保护阻断 | 回滚调用合法撤销，在相同用户锁及同一事务内完成 |
| 外部来源支付当次现金利息，成功后支出统计漏记 | 写入前明确拒绝该组合；能力接口声明不支持 |
| 服务器数据库同键并发返回唯一键错误 | 同用户写入先串行化，再核对请求摘要并回放原结果 |
| 大小写不同的幂等摘要在不同数据库下表现不一致 | 恢复只接受生产路径生成的规范小写摘要 |
| 伪造普通分配的撤销标记，阻断另一笔付款的合法撤销 | 普通分配必须无撤销标记；真正反向分配仍需逐项匹配原证据 |
| 有效付款或计划依赖被删除账户，恢复后无法纠错 | 有效依赖账户须可用；纯历史来源账户的 tombstone 仍保留 |

外部来源仍可偿还本金和已入账利息。当前费用统计依赖真实账户，因此
`source_kind=external` 且 `cash_interest>0` 暂时拒绝；没有创建虚假现金账户，
也没有把缺少费用凭证的付款静默视为正常数据。

### 复现及修复

- 初始统一入口测试在旧实现上出现 8 项单测失败和桌面、手机各 1 项入口 E2E 失败，
  原因分别是旧地址跳转、提醒账户列表未隔离及钱包缺少统一入口。
- 同步账户范围时会清除传入的 `view` 或 `operation_id`。两个新增单测先失败，
  修复后保留外部导航参数，只在用户主动切换范围时更新地址。
