# Web 小组件技术决策与风险边界

日期：2026-10-20。状态：开发前技术决策记录；当前实施结果见准备记录及 Task 6 交付报告，未变更依赖。

配套文件：[产品规格](../superpowers/specs/2026-10-19-web-widgets-design.md)、[实施计划](../superpowers/plans/2026-10-19-web-widgets.md)、[基线记录](../development/2026-10-19-web-widgets-readiness.md)。

## 1. 推荐结论

保留 Vue SPA、现有 Go API 和部署体系。视觉参考 macOS 小组件，实现仍是 Web。核心工作是有限网格、数据展示、草稿编辑和可达导航，不需要改造交易模型、服务端组件平台或通用插件系统。

推荐“现有栈 + 纯函数布局 + 小型交互适配层”。但不再把“完全自写拖动且禁止任何替代”当作先决结论：先完成 Gate 0 交互验证；失败时提交有证据的依赖方案，未经确认不安装。

### 功能关系与扩展边界

| 边界 | 本次责任 | 避免的成本 |
| --- | --- | --- |
| 功能目录 | 当前业务路由、名称、图标、归属与可固定状态；设置/安全/备份仍可达 | 不把组件 kind 当路由，不因取消固定而失去功能入口 |
| 组件目录 | 已实现能力的概览、真实状态与业务跳转；只有 account 首批可配置内容引用 | 不把完整编辑表单、批量操作或恢复/备份塞进小方块 |
| 读取层 | 复用现有财务来源、查询范围和变更刷新；不同来源可分开失败 | 不重新定义资金口径，不把不同时间返回的结果宣传为原子快照 |
| 编辑层 | 组件集合、端内顺序/尺寸、撤销、草稿与保存反馈 | 不触发交易删除、还款或账户写入 |
| 页面外壳 | 顶部/侧栏互斥投影、手机导航、主题/隐私/记账入口 | 不重建业务页面，不把桌面做成放大的手机 Dock |

库存、食品、药品、小票与 Agent 将来可以复用 WidgetFrame、画廊、状态反馈和导航目录。需要先定义真实数据、权限、采购/交易关联与失败恢复，再添加各自组件；当前不预建服务端插件表、通用事件总线、库存模型或新权限平台。AI 分析卡只展示已有报告，不因添加/刷新卡片调用生成、供应商测试或付费端点。

标题使用用户能判断目的的业务名称，描述只用于范围差异、空/错状态及不可逆操作的解释；不为每张卡添加副标题。图表只表达已有可验证数据，金额和动作不能依赖颜色、悬浮提示或图形单独传达。

## 3. 网格与拖动的竞争方案

| 方案 | 适用性 | 主要代价 | 本轮决定 |
| --- | --- | --- | --- |
| CSS Grid + Pointer Events 小型适配层 | 固定尺寸档位、按顺序排列、单组件拖动；与 Vue 状态一致 | 触摸取消、滚动、坐标及命中必须实证；不能发展成通用拖动引擎 | 首选候选，必须先通过 Gate 0 |
| SortableJS 类排序适配 | 主要管理顺序，可借用触屏/滚动机制 | 混合尺寸及 DOM/Vue 所有权需要额外验证，仍需非拖动操作 | 首选失败后的候选；没有选择或安装具体版本/包装器 |
| GridStack | 需要自由坐标、连续调整尺寸、多列布局引擎时有价值 | 会引入另一套位置/布局模型、命令式 DOM 管理和样式，退出成本更高 | 当前约束不足以证明值得引入 |
| 仅预设布局及移动按钮 | 复杂度最低、可访问性较易验证 | 不满足已确认的拖动体验 | 始终保留为替代操作，不作为静默缩水的最终交付 |

不把依赖数量当唯一优劣标准。如果当前适配层需要自己维护复杂碰撞、整套触摸引擎或跨窗口拖放，应停止扩写并重新比较候选。依赖候选进入项目之前须验证维护状态、许可、确切版本、Vue 配合、移动操作、包体和移除成本。

### Gate 0 必须证明什么

在含当前 WIP 的隔离副本中，仅用合成组件及既有工具链做一次交互验证，不连接任何 `/api`，不写正式源码。

1. 混合 S/M/L 能确定性重排，只有一个真实 DOM 顺序；Vue 用稳定实例 ID 作为 key。
2. 鼠标拖动与非拖动按钮都能排序；手柄以外仍能正常滚动、选择和点击。
3. pointercancel、Escape、失焦、容器缩放、跨端断点和退出编辑都能恢复原顺序；没有残留 ghost、监听器或误点击。
4. 当前容器自动滚动和嵌套滚动时坐标正确；取消拖动不提交草稿。
5. 焦点、模态画廊、滚动位置及现有对话框不因导航投影重建。
6. Chromium/Firefox/WebKit 自动化结果注明版本；模拟触摸、原生输入和物理设备验收分别记录。

这是开工验证，不是已经通过的结论。关键用例失败先修正或审视候选，不把失败拖到页面替换以后，也不静默取消拖动。

### Gate 0 实际结果（2026-10-20）

Gate 0 在含 937 个文件、219 项当前工作区状态的隔离副本中完成；未连接后端、数据库或账务 API，未回写原工作区。最终 Playwright 运行 44 项：42 通过、2 个明确跳过，0 失败。覆盖 Chromium 156.0.8078.4、Firefox 157.0、WebKit 27.2，另用 Pixel 7 模拟触摸配置验证单指轻触替代和合成 touch Pointer Events。跳过项分别是移动配置下的桌面专用布局断言与桌面自动滚动断言，均有桌面引擎覆盖或对应替代路径。

首轮 18/21 通过，三个浏览器都暴露“拖动中 Escape 后取消按钮不可用”；定位为探针事件时序和状态机问题，不是放弃拖动的理由。随后又复现：卡片重排会使被拖动节点移动，不能把 pointer capture 挂在会移动的卡片上；必须在开始时记录取消快照，由稳定网格容器承接 move/up/cancel/lost-capture，并在 pointerdown 当次绑定 Escape/blur。正式实现必须沿用这些约束。

验证还确认：拖动柄应位于当前滚动视口内；仅在手柄禁用原生平移，内容区仍可滚动；拖到滚动容器边缘要由持续计时器自动滚动，而不是只在 pointermove 时滚一次；跨 767/768 断点应取消拖动但保留编辑草稿；原生 `<dialog>` 的焦点约束和返回焦点可用。合成触摸输入不是物理设备实测。

证据目录：`/var/folders/l6/smy8mmk15898tpm0vddrbyt00000gn/T/sky-widget-gate0-20261020-081144-8308`；最终日志 `evidence/gate0-final-all.log`，构建日志 `evidence/build.log`。Gate 0 通过只证明有限 Pointer 适配层可行，不证明正式首页、业务数据、历史浏览器或物理手机已验收。

## 4. 布局真相与响应式

持久化只保存顺序、尺寸和内容引用，不保存 x/y 像素、容器宽度、拖动位置或绘制缓存。`packWidgets` 是唯一放置规则；CSS 负责绘制，拖动只提交新的序列。

- DOM 顺序来自当前端序列，不用 CSS `order`/dense 网格制造另一套阅读顺序。
- 桌面/手机偏好归属采用同一 `matchMedia('(max-width: 767px)')`。网格列数另按内容容器宽度选择 4/2/1；收起侧栏不能被误判成切换偏好端。
- S/M/L 是首选几何，不是强制截断的高度。文本放大、日历六周、错误说明或长金额时允许内在高度增长。
- 网格行以最小格高和可增长轨道绘制；不得用固定 height 或溢出隐藏破坏内容。临时占满行须传入 packWidgets 的同一投影，不能只改 CSS 跨列导致命中模型不同。
- 两列的小组件放不下完整关键内容时，以仅影响当前绘制的宽卡投影呈现；不改用户保存的尺寸。
- 金额完整保留精度，不使用省略号或虚构缩写；可读字号优先。极长数值可按数字分组完整换行，不缩成微字。
- ResizeObserver 更新由 requestAnimationFrame 合并，忽略无变化尺寸，避免观察自身写入导致循环。
- 拖动开始后冻结命中快照；合法缩放或端变化取消当前拖动，重新测量，不将旧坐标写入布局。

## 5. 类型、资源和偏好的明确边界

### 组件模型

`WidgetConfigByKind` 使用精确映射：`account` 必须有非空 `accountId`，其余首批 kind 使用空配置。`WidgetInstance` 为基于 kind 的可辨识联合，不允许给交易卡混入 accountId。

TypeScript 不校验 localStorage 的 JSON。运行时须验证版本、kind、支持尺寸、实例 ID、重复配置、顺序引用与额外字段。有效的空首页与“没有存储”不同；空首页显示添加/恢复入口，不自动插回六张卡。

画廊只展示已经接入渲染器和数据契约的组件。交付范围是六默认项加五个已有能力的可选项；11 个 kind 必须有完备 renderer 映射，不可以把目录声明当作实现完成。

### 资源状态

采用 `ResourceState<T>`：`phase: idle/loading/ready/error`、`data: T|null`、`queryKey`、`receivedAt`、可选错误信息。是否为空由对应业务返回值判断；是否过期由旧数据与请求状态判断。

这比互斥的 empty/stale 状态更准确：刷新时可能保留旧值，失败时也可能有旧值。失败有旧值应标明过期并可重试；跨用户/查询范围变动时清空旧值，不能用过期态继续展示另一个上下文的数据。

读取所有权：

| 数据 | 唯一读取方 |
| --- | --- |
| 账户、收支、预算、提醒、近期交易 | `useHomeOverview` |
| 指定账户记录/分类预算/家庭/借贷/AI | 同一读取层按查询 key 去重、按已启用实例加载 |
| 日历月份趋势 | 原 `CalendarView`，保留其刷新订阅，父层不再并行重复读取同一趋势 |
| 日历选中日期的交易与分页 | `useHomeOverview` 沿用原分页与代次 |
| 画廊预览 | 静态合成数据；不因缩略图重复访问真实 API |

### 分区持久化

首页与导航使用不同 key、不同版本化 envelope：`{ version: 1, revision: string, value: T }`。两者同属 origin/API 路径/已验证用户 ID，但分别读写。key 不通过改变版本后缀绕过未来版本保护。无新偏好默认顶部模式，不把旧 sidebar-collapsed 自动转换为新布局。

编辑只复制 home 草稿。钉住和导航模式更新不能被旧首页草稿的“完成”覆盖。首页集合/配置共享，端内尺寸及顺序独立；删除组件是两端共享操作，菜单应说明影响两端。

提交前核对该分区 revision；监听 storage 事件。发现同分区冲突时保留草稿、阻止静默覆盖，提供“载入最新布局”。没有冲突时只写当前分区。localStorage 不提供跨标签的事务性 CAS，本方案不宣称强一致；极短并发竞态仍属于首版 UI 偏好边界，不能宣传成多端同步能力。

损坏、未知未来版本和不可读数据不自动覆盖；只有明确选择恢复默认后才替换该分区。写失败保留草稿；写成功后再显示完成。不会删除旧 `theme`、`sidebar-collapsed` 或财务请求确认键。

## 6. 弹层、无障碍与兼容

- 画廊首选原生 `<dialog>.showModal()` 并在 Gate 0 验证焦点、Escape、滚动和移动布局；仅用于新画廊，不趁机重写现有业务弹窗。
- 钉住目录使用 Vue 控制的导航 disclosure；链接和钉住按钮为并列元素，不嵌套按钮。没有完整 menu 键盘语义就不标 `role=menu`。
- 不以 HTML Popover、CSS Anchor Positioning、View Transitions、corner-shape、subgrid 或 Web Locks 为首版必需能力；NAS 的普通 LAN HTTP 也要能使用基本布局与编辑。
- 无 backdrop-filter 时回退到不透明表面；减少动态效果、增强对比、键盘焦点在回退状态仍清楚。
- Tailwind 静态映射完整类名，或使用 CSS 变量/style 表达尺寸；不拼接 `col-span-${n}` 之类运行时类名。
- 44px 是项目操作舒适性目标，不宣称它就是所有 WCAG AA 条款的最低尺寸。
- 非拖动替代必须可以点击/轻触完成，键盘也可达。仅提供键盘快捷键不能替代单指针排序。

浏览器基线不变：Chrome 111、Firefox 128、Safari 16.4。Vite target 不是 polyfill，也不能证明所有新增 CSS/DOM API 都适配。Playwright 自带新浏览器通过只是引擎回归，不等于历史最低版本或物理 iPhone 实测；缺少设备/版本时明确未验证。

## 7. 性能与维护成本

六个默认组件在首页路由块中静态导入；画廊及可选重内容按需导入。不要给每个小图标或小卡制造独立请求瀑布，也不把整套业务数据搬进新框架。

复用现有请求保护、mutation revision、货币/图标与错误展示约定。每个 kind 一个展示组件，尺寸是同组件分支，不拆成 33 个尺寸组件。不做通用插件容器、多级事件总线、第三方组件市场或另一套财务缓存。

沿用现有包体硬门槛。2026-10-19 的 111,462B CSS 仅是当时基线，距上限 8,538B；未运行新实现，不能宣称新界面已满足预算。参考 PNG 只在 docs 中，不能导入运行时。
