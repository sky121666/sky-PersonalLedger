# 多分期财务契约

已实现账户级多计划、显式付款与分配、纠错撤销和备份兼容，并接入现有 Vue Web。
现有 Go/Gin/GORM/SQLite 体系及依赖保持不变。
逐期摊销表、自动计息、真实退款和债务豁免不在当前范围。

## 账户与计划

- 只有创建新负债账户时，可明确传入 `debt_tracking_mode: "managed"`。
- 未传模式的账户仍为 `legacy`，旧账户没有启用或转换接口。
- 新模式期初欠款须非负；后续普通转账仍可产生溢缴款。
- 一个账户可以有多个计划，独立计划则明确使用 `scope: "standalone"`。
- 创建关联计划是划分已有欠款：减少未归计划欠款，不增加账户余额。
- 原始本金与纳入追踪时的本金分开，不能据此推算未登记的历史还款。
- 未来预计利息不进入欠款、余额校验或消费费用。
- 财务状态 `cleared` 表示当前本金与已入账利息为零，不代表银行已经出具合同结清证明。

已核对账户满足：

```text
账户余额 = 各计划本金与已入账未付利息之和
         + unplanned_debt
         - unapplied_payment
         + debt_unclassified
```

`debt_unclassified` 保存有真实账户变化、但缺少债务归属的差量。
它非零时，账户需要核对，新付款及分配拒绝执行。
此差量来自实际操作凭证，不从历史账差反算填补。
撤销该操作仍可按原始影响执行。

## 付款与分配

- `source_kind` 必须明确为 `account` 或 `external`。
- `account` 必须指定真实所属的付款账户；`external` 不伪造资金账户或账本交易。
- 现有支出统计必须有真实账户。外部来源可支付本金和已入账利息，暂不接收
  `cash_interest > 0`；请求在写入前明确拒绝，能力接口返回
  `external_cash_interest: false`。不能把这一组合静默记为费用零。
- 关联账户付款可以分到多个同账户计划、未归计划欠款及未分配部分。
- 独立计划付款只面向该计划，不允许账户级未分配金额。
- 计划分配由 `principal`、`booked_interest`、`cash_interest` 构成。
- `booked_interest` 已在账户中形成负债，支付时冲减欠款，不再次记费用。
- `cash_interest` 此前未计入账户欠款，支付时仅形成费用，不冲本金。
- 各计划分配加 `unplanned_amount`、`unapplied_amount` 必须等于总金额。
- 专用付款不允许超额冲债，不自动决定清偿顺序，也不静默接收遗漏差额。
- 普通转入新模式账户的转账自动形成一次 `transfer_payment`，保留原交易身份。
- 延后分配只能消耗该付款尚未分配的冲债金额，不能再扣现金或账户余额。
- 把已有冲债金额改为此前未入账的当次利息，需要纠正原付款，不能用分配接口改含义。
- `replace_operation_id` 可在一个事务内撤销旧分配并登记新分配。
- 所有专用写入要求幂等键，保留请求摘要和原操作结果。

新模式本金偿还为资金划转，利息费用只确认一次。独立计划没有目标账本账户时，
本金付款仍有资金变化记录，但 `debt_principal` 来源不参与消费统计。
旧模式与历史统计不重算。

## 撤销

- 保留原操作、原分配、账户影响及新增撤销证据。
- 原交易退出有效账务统计，不生成一笔普通收入伪装退款。
- 反向应用实际账户差量，不恢复旧余额快照。
- 撤销付款时先原子撤销仍有效的后续分配，再撤销付款本身。
- 缺少账户影响、分配或交易证据时拒绝撤销。
- 新模型生成的交易禁止普通编辑、单删和批删，附件编辑仍走既有校验。
- 计划开户操作只有在没有有效后续操作时可以撤销；关联债务回到未归计划部分。
- 关闭或删除旧提醒不改变新计划。现有 Lending 的删除及依赖保护保持原义。

## API

均位于 `/api/v1/debt`，沿用认证和 `ledger:read` / `ledger:write` 权限。

| 方法与路径 | 含义 |
|---|---|
| `GET /capabilities` | 查询契约版本及兼容能力 |
| `GET /plans?account_id=...` | 当前用户计划 |
| `GET /plans/:id` | 单计划 |
| `POST /plans` | 新建计划 |
| `POST /plans/:id/interest` | 明确登记已入账利息 |
| `POST /payments` | 登记付款及初始分配 |
| `GET /operations?account_id=...` | 最近 100 条操作 |
| `GET /operations/:id` | 操作、分配、账户影响及交易 |
| `POST /operations/:id/allocations` | 付款后分配或替换分配 |
| `POST /operations/:id/reverse` | 原子纠错撤销 |

`GET /operations` 保持数组响应和默认最近 100 条的兼容行为。
新增 `plan_id`、`standalone_only=true` 和 `before=<操作 ID>`：
先限定计划或独立计划范围，再按 `created_at DESC, id DESC` 分页。
计划归属、当前范围内的游标和页面读取共用一致快照；外用户或外范围的游标返回 404。
能力接口通过 `operation_history: true` 声明这组查询能力。

新接口拒绝未知字段和多个 JSON 根值。新客户端应先检查能力，
不得把分配请求降级发送到旧提醒付款接口。
旧模式接口保留；新模式账户的旧提醒付款等不完整业务写入返回冲突。
导入到新模式账户的交易也会关联操作，不能通过旧批量删除绕过撤销。
导入批次回滚在同一事务中撤销原操作及其有效分配；混合批次任一操作失败则整体回滚。

业务冲突：`40910` 为入口不兼容，`40911` 为账户待核对，
`40912` 为撤销证据或依赖不足；幂等冲突沿用 `40903`。

操作详情额外返回 `unallocated_amount` 及 `active_allocations`。
它们在同一读快照内计算，付款的可分配额度不依赖最近 100 条操作列表。
已撤销付款返回零额度及空有效分配列表；既有响应字段保持不变。

## Web 接入与客户端兼容

- “我的钱包”和“我的”统一进入负债管理 `/reminders`。页面内提供“账户与分期”
  和“还款提醒”两个分区，不再保留独立的分期管理导航入口。
  原 `/debt` 深链重定向到统一页面，保留账户、操作凭证等 query 参数。
- “账户与分期”沿用同账户多计划、独立计划及原财务操作；“还款提醒”保留
  旧提醒、还款和进度口径，两个分区的余额不相加。切换分区保留账户范围和未决请求。
  离开分区时关闭空闲弹窗；正在提交的请求保留上下文，非当前分区的弹窗不覆盖页面。
- 新负债账户可显式选择多分期模式。已有账户不提供转换入口，旧模式仍为默认值。
  新建旧提醒不提供多分期账户；编辑已有提醒保留原绑定，不自动解绑或变更历史。
- 页面提供计划建立、账户级或独立计划付款、已入账利息、付款分配、
  原子重分配、操作凭证与纠错撤销；预计未来利息单独展示。
- 每个计划均有操作凭证入口，包括已取消计划。可按计划筛选并加载更早凭证，
  独立外部付款不会因其他账户超过 100 条操作而失去纠错入口。
- 交易明细和账户流水可跳转到关联分期凭证。
  新模型投影不能通过普通编辑或删除入口绕过撤销。
- 新页面沿用现有蓝色、玻璃卡片、明暗主题、Lucide 图标与响应式布局，
  未新增组件库或依赖。
- 页面先检查契约能力。旧后端返回 404 时提供兼容提示，旧账户创建
  不发送新字段，也不将分配请求降级为旧提醒付款。
- 只有旧版操作详情、尚无完整额度字段时，保守停用后续分配。
  网络错误、账户待核对、凭证变化及存储异常都有明确反馈，服务端为最终裁决。
- 金额表单按整数分检查精度、合计与付款分配，拒绝负数、科学计数法、
  超过两位小数及不安全整数。
- 写请求先按当前用户保存完整 payload 和幂等键到 `sessionStorage`。
  丢失响应或幂等冲突时保留原请求，刷新后可确认同一操作；确认前暂停新操作。
  后续确认被限流、认证或业务拒绝，不能证明原请求未提交，继续保留原键。
  只有首次被明确拒绝且不属于超时、限流或幂等冲突时，才释放该请求记录。
  此保护限于当前浏览器标签页的会话，不承诺关闭标签页后的持久恢复或跨标签同步。
- Web 弹窗支持 Escape、Tab 焦点约束和关闭后返回入口；大列表、长名称、
  小屏表单及明暗主题使用隔离账本验证。
  原入口被禁用、移除或隐藏时，关闭后将焦点放回页面标题。

## 迁移、备份与回退

- schema 13 为新增模型、引用与状态字段；不建立旧计划、不回填旧还款、不重算余额。
- 本轮仅在隔离数据库运行迁移。以后启动新版后端会按既有机制执行待运行迁移。
- 只有旧模式数据时仍导出备份 2.4；包含新模式数据时导出 2.5。
- 2.5 同时保存计划、操作、分配、交易引用和账户影响，计入既有大小及条数限制。
- 恢复前验证归属、完整引用、资金影响、分配累计、撤销关系与账户核对式。
- 普通分配不能携带撤销标记；有效操作及未取消计划依赖的账户须仍可使用。
  已撤销付款仅保留历史引用的旧模式来源账户仍可按原规则恢复 tombstone。
- 验证不通过时，不清空目标记录、不替换附件。
- 新后端继续接收 2.1 至 2.4，恢复后保持旧模式，缺证据历史撤销继续保护性拒绝。
- 旧程序不能安全读取 2.5；不可为降级而删除新凭证或修改版本号。
- 数据库没有向下迁移承诺。未来部署后若需回退，应同时恢复升级前的隔离验证备份与匹配程序，
  不能仅回退可执行文件。
- 既有软删除附件保护、GC 宽限和旧完整备份保留政策不变。

## 验证边界

回归使用临时 SQLite、临时附件和 httptest；没有接入正式账本。
MySQL/PostgreSQL 的在线连库与多实例部署需单独验证。
本阶段已接入 Web。移动端尚无新的分配交互，保持其旧数据路径及明确错误反馈。
