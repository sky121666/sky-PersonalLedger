# Personal Ledger v1.0.11

**历史候选状态：安全扫描阻断，未发布。** 发布运行 `37410524297` 已完成双架构构建，但 amd64 Trivy 扫描发现 OpenSSL `libcrypto3/libssl3 3.5.7-r0` 的 `CVE-2026-14456`（修复版 `3.5.8-r0`）及 Go `golang.org/x/crypto 0.53.0` 的 `CVE-2026-56854`（修复版 `0.55.0`）。arm64 扫描、publisher 与 Release 步骤均跳过，未发布镜像或 Release。

既有 `v1.0.11` tag 必须保留且不可覆盖，不得移动、删除或重跑旧源码补发。后续版本使用 [v1.0.12](v1.0.12.md)。以下保留原候选说明，不作为当前发布完成的证明；扫描记录不等于已观察到实际入侵或业务数据污染。

本版本承接账本恢复、异步表单、登录生命周期、移动缓存和 AI 自动化修复，并要求签名证明具有可信来源约束。源码文档不单独证明发布完成，正式状态以 [GitHub Release](https://github.com/sky121666/sky-PersonalLedger/releases/tag/v1.0.11)、对应运行记录和公开资产核验为准。只有确切源码的来源反例、独立复审和发布门禁通过后，才可创建该版本产物。

[v1.0.10](v1.0.10.md) 因证书调用 ref 未受约束而停止发布，既有 tag 不得覆盖。同仓库普通分支能够签发有效签名，不等于该证明来自受保护发布流程；此前测试没有覆盖这个反例。

## 主要变化

- 专用 2.4 备份合同保留删除、禁用、归档和已结清状态；缺少必需集合在清空账本前被拒绝。有效 2.1–2.3 可继续读取，旧备份已丢失的删除状态无法凭空补回。
- Web 固定交易编辑目标，独立保存归属成员与付款人。首页可选查询失败不隐藏资产，未知数额不显示零；换月和换日结果绑定查询身份。
- 浏览器认证请求排队并绑定会话代次；Cookie 退出可在 Access Token 过期时撤销该刷新会话及轮转后继，不能误撤销独立新登录。失败刷新、无效旧 Cookie 退出和改密迟到响应不再删除新登录 Cookie。
- Flutter 恢复后重建仓库、缓存和保活页面；离开恢复页面也执行成功后的失效，旧会话迟到回调被撤销。模板账务成功与辅助列表刷新结果分开。
- 原生导出使用系统保存入口，Flutter Web 发起本地下载并提示确认；取消或失败不会说已保存。macOS 只申请用户所选文件的写权限。
- AI 类型实际进入供应商任务，有效总结和字段类型经过校验；报告完成只合并运行记录，不重新启用用户已关闭的计划。每用户两项并发、每分钟六次尝试、输出最多 4096 tokens。
- 发布库存继续覆盖 v1.0.9 基线到候选提交的全部路径；真实备份演练绑定版本、源码 SHA 和运行指纹。扫描证明还必须核对证书实际调用工作流、触发 ref 和来源提交，不能只相信谓词中的自报字段。正常发布与恢复分别绑定产品 tag SHA、受信工具 SHA；目标合同见 [当前证据合同](../quality/current-release-evidence.md)。
- 更新已确认有公告的 Web 依赖；保持 Vue 3/Tailwind 3，并验证 selector 更新后的 CSS 与原版字节一致。无上游修复版的 braces 使用精确版本源码补丁，默认限制递归深度，冻结安装与实际消费链回归接入 CI。

## 安装、升级与回滚

部署前核验该版本 Release 存在，再下载版本专属 `docker-compose-v1.0.11.yml`、`.sha256` 与 `docker-scan-proof-v1.0.11.jsonl`，确认 checksum、签名来源与公开资产身份一致后使用。Compose 必须固定 GHCR digest；仓库基线 Compose 的旧 digest 不在发布后循环改写。

升级前停止写入，保留数据库、附件、配置和凭据密钥的一致性副本及旧镜像 digest。回滚到 v1.0.9 使用升级前副本；不得修改 2.4 备份版本号后强交旧读取器。升级后的新增业务数据需另行审查迁移，不声称自动跨版本逆向合并。

本次数据库从 schema 10 升级至 11；旧版本拒绝更高 schema。独立容器演练确认 10→11→10 及回滚副本的余额、删除/禁用状态和附件不变。当前停止容器未验证 HTTP 请求排空，需先停业务写入；没有优雅退出的声明。

## 验证与限制

此前候选的业务测试以 Go 普通/race/vet、SQLite/PostgreSQL/MySQL、Web 单元/构建/真实后端 Playwright、Flutter analyzer/单元/Chrome 导出与 flutter-tester 真实后端为基础，但没有覆盖签名来源反例。新增反例在旧校验器的 RED 已归档；来源修复阶段的 17 项本地来源回归通过，不能代替本轮独立复审或真实远端验收。发布须绑定确切源码 SHA，验证来源约束、签名、扫描、公开资产身份和容器健康/持久化，最终结果以对应 CI run 和资产为准。

正式范围为 Docker/Web；无签名 APK/AAB/IPA、实体设备、商店或手工 VoiceOver/TalkBack 通过声明。单可写实例、不提供离线写入、多租户或独立家庭成员权限。AI 约束为进程内请求限制，重启重置，不是金额预算。已发 Access JWT 仍有效至到期；无 Web Locks 时浏览器认证顺序只保证当前页面。

生产依赖审计为 0。全依赖版本扫描仍命中上游 braces 3.0.3 的一项 high 公告；项目源码补丁已独立复验，未改版本号、屏蔽公告或降低级别。两种证据及维护方式见 [构建依赖安全](../development/dependency-security.md)。

自我批判和失败反证规范见 [自动修复合同](../development/autonomous-repair-contract.md)，机器证据及信任来源见 [当前证据合同](../quality/current-release-evidence.md)，执行步骤见 [v1.0.11 发布运行手册](../quality/final-release-runbook-v1.0.11.md)。
