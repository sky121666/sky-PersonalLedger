# 首页原始容器宽度恢复

日期：2026-10-20。本记录补充并更正上一轮卡片视觉恢复中遗漏的桌面容器尺度。

## 源码依据与改动

`HEAD:web/src/views/HomeView.vue` 的原首页内容区为 `max-w-3xl mx-auto px-4 md:px-8`，最大宽度 768px，居中且两侧留白。组件化之后使用了最大 1024px 的 `max-w-5xl`；它并非无限全宽，但明显宽于原设计。

本轮将当前 `HomeView.vue` 的 `max-w-5xl` 恢复为 `max-w-3xl`。与本轮前副本逐字比较，HomeView 只有这一处 class 变化，脚本、账务请求、偏好、导航均未修改。

窄容器同时暴露了三处排版问题，集中在 `home-cards.css` 修正：

- 资产卡以卡片实际宽度适配字号和间距，普通 Demo 金额不需要内部纵向滚动。
- 收支卡收紧列间距和字号，`+15,860.00 / -4,515.00 / 11,345.00` 保持各自单行。
- 账户横向小卡收紧内边距，避免新增无意义的纵向滚动。

采用卡片容器查询，未新增依赖，也未改变颜色、卡片尺寸跨度、已保存布局或财务规则。

## 实测

1440px 桌面、收起的侧栏模式：外层内容区宽 768px，内部网格 704px，相对主内容区左右各留 294px；小卡 164×164，中卡 344×164，大卡 344×344。390px 手机仍为 358px 网格、小卡 171×171；继续使用原两端布局。

Demo 浅/深主题、窄版画廊及手机显示已检查；最终桌面截图中收支三个金额均为单行，资产与账户内容无纵向溢出。用户原有内置预览标签已经刷新，保留其深色主题和钉住配置。

## 验证结果

- 限宽测试修复前在 1440px、1920px 均失败：实际 1024px，期望 768px；修复后通过。
- 缩窄后资产内容曾溢出 27px，收支金额曾折成两行；已增加相应断言并修复。
- 最终五个受影响 E2E 文件，Chromium、Firefox、WebKit 各 70 项，共 210 项通过，0 失败。
- 两条边缘拖动用例调整为 1440×600 的明确可滚动视口，并增加“确有滚动空间”的前置断言；保留原滚动、取消和内容高度断言。
- 动画边界用例等待首页真实加载完成后再测试抓取，避免加载更新与人工暂停动画混合。没有为这些用例修改业务或拖动实现。
- 6 个相关单测文件、49 项通过；应用/测试类型检查、构建、brace、附件和原包体门槛通过。
- 现有 Demo 的 7 张关键财务表前后指纹一致；93 个构建文件经 HTTP 回读与本地哈希一致。
- 本轮只改动 2 个产品文件、3 个既有 E2E 文件，并新增本记录与截图；其他既有 WIP 指纹保持不变。无暂存、提交或推送。
