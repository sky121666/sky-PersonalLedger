## 业务不变性

1. 删除、备份、恢复不能改变活动数据集合、余额、统计和历史关联。
2. 不完整备份在任何清空操作之前被拒绝；明确的空集合与缺失字段不能混淆。
3. 编辑表单、请求和保存目标必须属于同一交易和打开代次。
4. 归属成员与付款成员独立保存；只修改备注不能改变任一原始成员。
5. 退出、新登录、恢复账本会失效旧请求或缓存；旧结果不能覆盖新状态。
6. 用户关闭自动 AI 报告后，正在结束的任务不能重新启用它。
7. 核心写入成功与辅助读取失败分开报告；辅助失败不能诱导重复记账。
8. 未知或过期数据必须标明状态及实际期间，不能显示为当前零资产或新月份金额。
9. 报告类型必须指导模型；无有效正文或字段类型错误不能成为 completed 缓存。
10. 文件写入后用户有实际保存、分享或打开入口。
11. 每份发布证据绑定版本、源码和执行结果；干净检出同样检查已提交差异。

## 设计决定

### 备份

新增明确版本的备份序列化层，保留软删除时间，同时继续排除凭据与内部 ProviderRevision。优先使用新格式 2.4，保留 2.1–2.3 的明确兼容读取。旧格式已经丢掉删除状态时不能推断或伪造它；文档准确说明该限制。必需集合按格式版本定义，避免为修复 partial JSON 而拒绝项目真实生成的旧备份。新旧格式均保留引用、大小、深度、跨用户和路径验证。

### Web 与 Flutter

Web 对编辑和会话增加代次校验，关闭/切换时立即使旧工作失效；表单保存固定本次目标。两个成员字段分别管理，可共享明确的默认选择但不能覆盖未编辑的历史值。首页核心/可选读取分别接收结果；统计数据与查询身份一起保存。Flutter 恢复触发全账本缓存失效，模板 apply 成功后立即确认账务结果；导出复用已安装 file_picker 的系统保存能力，不引入无关依赖。

### AI

提示词携带 report_type 与对应要求，输出规范为包含非空 summary 的对象，其他字段有明确类型。允许兼容供应商返回有效纯文本并包装为 summary；拒绝 null/数组/空对象/错误字段类型。更新 prompt version 以避免旧缓存绕过新契约。用户配置和任务运行记录采用原子合并或版本检查；发送前重读开关。设置适当输出长度、用户级生成并发与频率限制，并如实区分令牌限制与费用上限。

### 交付

发布清单基于基线 tag/SHA 到候选源码的 diff，而不是仅依赖 git status。恢复演练生成机器可读结果，绑定源码指纹、版本、备份格式、执行时间和不变性断言。发布推广后保留绑定扫描、源码和 digest 的持久证明；恢复工具读取可信证明时仍保持 fail closed，不把声明文件当扫描证据。

## 批判性审查

每个修复必须回答：旧测试为什么没发现；新增测试能否在旧实现上失败；兼容输入是否被错误拒绝；成功副作用之后失败会不会引导重复；并发或重启是否破坏不变性。使用控制响应和合成数据库给出反证，禁止断言仅复述实现。独立审查须检查规范符合性与代码质量，主代理复核关键结论。
