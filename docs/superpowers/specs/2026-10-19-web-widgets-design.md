# Web 小组件首页与导航设计规格

日期：2026-10-19。状态：已实施的产品规格；阶段执行与最终验证见实施计划和 Task 6 交付报告。

2026-10-20 技术细化见 [技术决策与风险边界](../../architecture/2026-10-20-web-widgets-technical-decisions.md)，实施顺序见 [开发计划](../plans/2026-10-19-web-widgets.md)。以下为产品规格，类型、分区存储及交互验证门槛由技术决策补足。

## 1. 已确认的目标与边界

沿用现有 Web 技术栈，以 macOS 小组件的比例、内容层级、尺寸预览和编辑方式组织首页。页面背景采用纯色，导航和浮层保留蓝色玻璃语言。用户可以配置首页组件、分别调整桌面与手机布局，并钉住常用功能。

- 保留当前全部未提交改动；不暂存、不提交、不推送。
- 不修改后端、公共 API、数据库结构、认证规则、历史余额、备份格式、CI 或 Docker。
- 不访问正式数据库、真实附件或真实账单；浏览器验收只使用新建隔离环境及合成数据。
- 不升级依赖、不添加 UI 框架或拖动库；继续使用 Vue、TypeScript、Pinia、Tailwind、Lucide。
- 保留 TypeScript 6.0.3 例外及现有构建目标：Chrome 111、Firefox 128、Safari 16.4。
- 库存、食品、药品、小票和 Agent 不在首批开发范围；不展示成已可用功能。
- 图片是结构参考；文字规格优先。纯色背景、真实接口、财务语义优先于生成图细节。

参考图片：[结构参考说明](../../design/home-widgets/README.md)。

## 2. 开发前源码依据（2026-10-19）

| 入口 | 已核对的事实 | 开发约束 |
| --- | --- | --- |
| `web/src/views/HomeView.vue` | 集中加载账户、统计、交易、提醒、预算、借贷、家庭和 AI，包含列表/日历及请求代次保护 | 提取展示层，不复制计算或丢失刷新、分页、日历能力 |
| `web/src/views/LayoutView.vue` | 桌面侧栏、手机底栏、全局记账弹窗及路由滚动 | 导航模式切换不得重建路由页面或清空弹窗 |
| `web/src/router/index.ts` | 首页为 `/`；负债入口为 `/reminders`；`/debt` 为兼容跳转 | 不新增业务路由，不把生成图的路径当真实路径 |
| `web/src/api/auth.ts` | `authApi.getProfile()` 返回稳定的数字用户 ID | 复用现有只读接口，不解码 Token、不修改认证 store |
| `web/src/stores/auth.ts` | `sessionGeneration` 可标识会话失效 | 忽略旧会话迟到结果；退出时清空内存数据与编辑草稿 |
| `web/src/api/account.ts` | 账户列表返回服务端资产、负债、净资产汇总 | 不在组件中重新汇总账户以改变口径 |
| `web/src/api/reminder.ts` | `DebtSummary` 有名称、还款日、相隔天数，没有下一笔金额或提醒 ID | 不显示原型中的虚构下一笔金额，不按同名匹配提醒 |
| `backend/internal/service/reminder.go` | 提醒汇总与账户分期是不同范围 | 保留“还款提醒，不含账户分期”含义 |
| `web/src/api/budget.ts` | 汇总可用于当前预算；分类明细可由既有 `getList(month)` 读取 | 大号预算按需共用一次明细读取，不增加 API |
| `web/src/composables/useLedgerMutation.ts` | 多页面共用账务变更版本 | 记账后刷新已有组件，不重排组件 |

当前接口没有独立账本 ID。首批持久化隔离为“当前部署来源/API 路径 + 已认证用户 ID”，不是多账本实现。未来若增加真实账本身份，再另行扩展命名空间；不构造假账本 ID。

## 3. 视觉与响应式规格

| 项目 | 固定约定 |
| --- | --- |
| 浅色页面底色 | `#F2F2F7`，纯色 |
| 深色页面底色 | `#0B0B0D`，纯色 |
| 主色 | `#007AFF` |
| 组件表面 | 浅色近白、深色 `#1C1C1E`；内容表面以不透明为主 |
| 玻璃范围 | 顶部导航、侧栏、菜单、组件画廊；不在每个组件上叠加高强度模糊 |
| 间距/内边距/圆角 | 组件间距 16px，标准内边距 16px，圆角 24px |
| 字体 | 复用现有字体；金额等宽数字；正文通常 14–16px，辅助标签不低于 12px |
| 操作区域 | 至少 44×44px；图标视觉尺寸可为 18–22px |
| 动效 | 常规约 180ms；减少动态效果时取消位移动画；不引入动画依赖 |

禁止页面壁纸、背景曲线、背景图片、背景渐变、发光轮廓和伪造趋势线。允许内容图表、预算环和必要的蓝色选中态。图片中的背景不进入实现。

桌面采用四个基础列；可用内容宽度不足 688px 时降为两列，再不足 328px 时降为一列。按容器宽度判断，侧栏变化也会触发重排。

- 小：一格；中：两格宽、一格高；大：两格宽、两格高。
- 四列时基础格最大 240px，居中排列；较窄时随容器缩放。
- 两列时，小组件可并排；中/大组件占满两列。
- 一列、长金额、长账户名或文字放大时允许组件增高/占满行，禁止缩小金额或遮挡文字。
- 布局计算保持源顺序及键盘阅读顺序；不使用 `grid-auto-flow: dense` 随意补洞。
- 桌面/手机偏好端由 `matchMedia('(max-width: 767px)')` 决定，列数由内容容器宽度决定；收起侧栏不切换偏好端。
- 底部导航预留安全区与至少 96px 内容补偿，最后一行可滚动到导航上方。

## 4. 首批组件目录与默认布局

尺寸以真实内容为依据，不强制所有组件支持三种规格。

| kind（内部稳定 ID） | 名称 | 支持尺寸 | 来源/点击目的地 |
| --- | --- | --- | --- |
| `netAssets` | 净资产 | 中 | `accountApi.getList()` 汇总；账户页 |
| `monthlyFlow` | 本月收支 | 中 | `statisticsApi.getOverview()`；统计页 |
| `budget` | 本月预算 | 小/中/大 | `getSummary()`；大号按需 `getList(month)`；预算页 |
| `reminders` | 还款提醒 | 小/中 | `getDebtSummary()`；`/reminders?view=reminders` |
| `transactions` | 最近交易 | 中/大 | 既有交易列表；详情沿用现有托管交易保护 |
| `accounts` | 我的账户 | 中 | 共用账户列表；账户页 |
| `account` | 指定账户 | 小/中 | 已授权账户列表；中号近期记录按账户用既有查询读取 |
| `calendar` | 收支日历 | 大 | 复用 `CalendarView.vue` 及已有日期交易分页 |
| `lending` | 借贷往来 | 中 | 既有借贷汇总及页面 |
| `family` | 家庭支出 | 小/中 | 既有家庭汇总及页面 |
| `ai` | AI 分析 | 中 | 既有报告；未配置/未生成时显示真实状态，不调用 Agent |

默认六项顺序：`netAssets M → monthlyFlow M → budget S → reminders S → transactions L → accounts M`。四列呈现两张中号顶行；下一行两个小号与大号交易；大号下半行旁放中号账户。

提醒首批呈现后端返回的“今天/几天后”、约定还款日和名称；无金额来源就不显示金额，不能把待还总额当下一笔金额。没有活动提醒时不得把 `days_until_next=0` 解释为“今天”。不根据浏览器月份拼接未经证实的实际到期日期。

预算用既有汇总展示；超支时保留负剩余与真实百分比，环形图绘制限制在 0–100%，不能把超支数字截成正常。未设置预算、失败和真实为零分别呈现。

普通收入/支出沿用现有配色；转账中性色，无收入/支出正负暗示。提醒口径放入信息说明及可访问名称，中号可显示短范围说明；不在小方块塞整段文案。

同类组件配置不同可并存；完全相同的 kind、内容配置则定位已有组件。首批只有 `account` 接受 `accountId` 配置，不添加尚无接口支持的任意筛选器。

## 5. 编辑、画廊与持久化

常态只有“编辑小组件”入口，刷新首页数据仍有可访问的明确控件。编辑时创建草稿，上方显示“取消 / 添加小组件 / 完成”，低频恢复默认放入菜单。

- 只通过编辑态手柄拖动。普通点击保持业务含义，拖动不能打开详情或发起业务写入。
- 吸附网格、不重叠；取消指针、Escape、失焦均取消拖动并恢复原位置。
- 编辑态允许轻量移除标记；移除仅修改草稿，并可撤销，不走财务删除确认。
- 组件菜单提供支持尺寸、配置、上移、下移；键盘无需拖动也能完成布局。
- 上移/下移也必须可点击或轻触，不能只提供键盘替代。移除入口明确说明影响桌面与手机；有效空首页提供添加和恢复入口，不强制插回默认卡片。
- 画廊左侧分类/搜索，右侧为同一组件的真实尺寸预览。必须先选必填内容再添加。
- 关闭画廊返回当前草稿；“完成”才保存整个布局；取消不写存储。
- 恢复默认明确标为“恢复桌面与手机默认布局”，重置草稿中的共享集合及两端尺寸/顺序，不改钉住和导航模式；可撤销或取消，完成前不落盘。
- 拖动、切换导航或数据刷新不卸载业务视图，不清空日期、筛选、滚动或未提交输入。

本机偏好为版本化 JSON，仅保存组件 ID、kind、内容引用、尺寸、顺序、导航模式及钉住 ID。不保存金额、交易、头像、Token 或私人内容。不改既有财务备份格式，不宣称跨设备同步。

首页与导航分区保存，并各自核对 revision；完成首页草稿不能覆盖期间更新的钉住或导航模式。检测到其他标签修改同一分区时保留草稿并提供载入最新布局，不静默覆盖；本机存储不承诺事务级并发一致性。

共用组件集合与内容配置，分别保存 `desktop`、`mobile` 的尺寸和顺序。新增组件加入两端，移除组件两端同步；仅调整尺寸/顺序只影响当前端。窗口缩放只是投影，不能自动落盘覆盖另一端配置。

复用 `getProfile()` 获取用户 ID 后才读取偏好；旧会话结果失效。身份未知/接口失败先使用未个性化默认态，不读取其他人的配置。存储异常或损坏时提供恢复默认/重试，内存编辑仍可用，但不能假报保存成功。未知未来版本保留原文，不自动覆盖。

账户列表读取失败时不能误判指定账户被删除；只有成功列表确认缺失时才显示“账户不可用”。不自动删除对应组件或创建账户。

## 6. 顶部、钉住侧栏与手机导航

一个功能目录决定名称、图标、目的地与固定状态。保留当前路由，不生成新路径或改变权限。

- `首页` 和 `更多` 始终可达；默认钉住 `transactions`、`statistics`、`budgets`。
- 其他可固定入口复用 `accounts`、`reminders`、`lendings`、`family`、`ai`、`report`、`categories`、`tags`、`templates`。
- 设置、安全、备份继续在原设置界面；设置入口始终可达，不增加危险操作快捷组件。
- 顶部模式不显示侧栏；侧栏模式不显示顶部主菜单。全局记账、主题和金额隐私操作保持可达。
- 无新偏好时默认顶部模式；侧栏展开名称是会话内展示，不迁移或删除旧 sidebar-collapsed 设置。
- 紧凑侧栏为图标栏，名称通过悬浮/焦点提示可读；必要时可展开名称。
- 固定菜单与实际导航状态必须一致；取消固定不等于移除首页组件。
- 顶部宽度不足时进入更多菜单；手机为首页、前三个固定入口、更多，始终保留短标签。
- `/account-logs` 归属账户，负债兼容跳转仍归属 `/reminders`；不再把所有业务页都高亮成“我的”。
- 切换模式不改变路由、草稿或业务数据。

## 7. 数据复用、性能与兼容

保留 `Promise.allSettled` 的分源错误处理、`createRequestGeneration` 的迟到结果保护、`useLedgerMutationRevision` 的刷新链路。组件不各自复制这些计算。

相同来源共用快照与读取；同一指定账户的记录按账户 ID 去重。家人、借贷、AI、分类预算等可选内容按启用状态读取，未启用的内容仍能从原页面访问。画廊预览使用静态合成数据或已授权快照，不为每个缩略图请求接口。

首批用现有 CSS Grid、Pointer Events、Vue 实现有限的排序与尺寸切换。没有任意自由画布、连续缩放、多选或插件机制，因此不先引入新拖动依赖。先在不连接 API 的隔离实验中验证混合尺寸、触摸/滚动、取消和弹层焦点，再进入页面替换；若证明此实现不合适，单独提交依赖取舍，不静默安装。

保留生产包门槛：总原始体积 1,000,000B，总 gzip 400,000B，最大 JS 200,000B，最大 CSS 120,000B，入口 HTML 20,000B。画廊及低频面板可按需加载，CSS 类名须可被当前 Tailwind 扫描。

## 8. 验收与执行范围

先完成隔离交互可行性验证，再完成纯配置/布局/存储测试，最后接现有数据、导航和编辑交互；每步都保留可回归的旧能力。目录中的全部 11 个 kind 均须有渲染器及真实状态处理，不能只声明可添加入口。

必须验证：默认六组件、不同账户并存、重复拦截、草稿取消/完成/撤销、两端独立顺序、损坏存储、未知版本、存储拒绝、身份切换、迟到响应、账户消失、预算为零/超支、转账语义、提醒无金额、空/错/旧数据、日历日期与第二页数据。

桌面/手机至少覆盖 320、390、768、1280、1440px，浅深主题、长名称、长金额、文字放大、减少动态效果、键盘菜单与排序、触屏滚动和拖动取消。Chromium、Firefox、WebKit 使用现有隔离脚本；不把模拟视口当作物理手机实测。

本次准备阶段不实施页面替换、不运行数据库或服务、不做依赖升级。后续按配套计划逐项实施和验证。
